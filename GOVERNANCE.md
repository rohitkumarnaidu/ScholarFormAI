# Governance

## Project Structure

The Automated Manuscript Formatter (AMF) project is governed by a community-driven model with the following roles:

### Maintainers

Maintainers are responsible for the overall health and direction of the project. They:

- Review and merge pull requests
- Set technical direction
- Manage releases
- Moderate community discussions
- Enforce the Code of Conduct

### Contributors

Contributors are community members who submit pull requests, file issues, or participate in discussions. Anyone can be a contributor.

### Users

Users are individuals or organizations that use AMF in their projects or workflows.

## Decision Making

- **Technical decisions** are made by maintainers through lazy consensus
- **Major changes** are discussed via RFC (Request for Comments) process
- **Governance changes** require supermajority (2/3) of maintainers

## Voting

- **Simple majority** for routine decisions
- **2/3 supermajority** for governance changes and new maintainer additions
- Voting period is 7 days unless otherwise specified

## Sub-Projects

- **Core**: Backend API and formatting engine
- **Frontend**: Web UI
- **CLI**: Command-line tool
- **SDK**: Python client library
- **Docs**: Documentation website

Each sub-project has at least one maintainer.

## Communication

- **GitHub Issues**: Bug reports and feature requests
- **GitHub Discussions**: Community Q&A and ideas
- **Maintainer meetings**: Bi-weekly (public agenda and notes)
- **RFCs**: Published as GitHub issues with the `rfc` label

## Code of Conduct

All community members must follow the [Code of Conduct](CODE_OF_CONDUCT.md). Violations should be reported to the maintainers.
