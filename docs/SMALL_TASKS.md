# Small Tasks for New Contributors

## Overview

ScholarForm AI identifies small, well-scoped tasks that are suitable for new or casual contributors. These tasks are labeled in the GitHub issue tracker to make it easy for anyone to find a place to start contributing.

## Issue Labels

We use the following labels to help contributors find appropriate tasks:

| Label | Description | Typical Time |
|-------|-------------|-------------|
| `good first issue` | First-time contributor friendly | 1-3 hours |
| `help wanted` | Tasks where maintainer guidance is available | 2-8 hours |
| `small fix` | Targeted, well-defined change | < 2 hours |
| `documentation` | Docs improvements, typo fixes, clarifications | 0.5-2 hours |
| `test` | Test writing or improvement | 1-4 hours |
| `bug` | Confirmed bug with reproduction steps | 2-8 hours |

## Where to Find Tasks

1. **GitHub Issues**: Browse open issues filtered by label.
   - [good first issues](https://github.com/rohitkumarnaidu/ScholarFormAI/labels/good%20first%20issue)
   - [help wanted](https://github.com/rohitkumarnaidu/ScholarFormAI/labels/help%20wanted)
   - [small fix](https://github.com/rohitkumarnaidu/ScholarFormAI/labels/small%20fix)

2. **Milestones**: [Open milestones](https://github.com/rohitkumarnaidu/ScholarFormAI/milestones) contain upcoming work.

## Examples of Small Tasks

### Documentation
- Fix a typo in documentation.
- Add a code example to an API reference.
- Improve a tutorial with screenshots.
- Translate documentation to another language.

### Testing
- Add unit tests for an existing function.
- Add edge case tests for a utility.
- Improve test coverage for a module.
- Add Playwright E2E test for a user flow.

### Code
- Add input validation for an API endpoint.
- Fix a lint warning across the codebase.
- Refactor a small function for clarity.
- Add error handling for an edge case.
- Improve logging in a service.

### CI/CD
- Add a new GitHub Actions workflow.
- Improve caching in an existing workflow.
- Add a new lint rule configuration.
- Update dependency versions.

## Getting Started

1. Find an issue labeled `good first issue` that interests you.
2. Comment on the issue to let others know you're working on it.
3. Read [CONTRIBUTING.md](../CONTRIBUTING.md) for setup and workflow guidance.
4. Submit a pull request and tag the issue.

Maintainers will provide guidance and mentorship throughout the process. Don't hesitate to ask questions!
